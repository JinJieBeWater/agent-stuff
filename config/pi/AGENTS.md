## 沟通与表达

- 默认中文，代码、命令、路径、错误信息和 API 名称保留原文；用户指定语言时遵循。先在对话中直接回答，再按需展开；agent 间交接已有长正文文件时，只回简要结论和路径。
- 聊天中向用户集中提问时用 `ask`：同轮问题一次提出，每题一个 prompt，首个 choice 为推荐项并标「（建议）」，理由写进它的 description。

## 实施与权限

- 先弄清真实约束，再选让正确行为不出意外的最小模型：复杂度不因已存在而保留，机制不为显得有架构感而加。量两次再切，同时 YAGNI，压住范围蔓延。
- 规则和手上的任务冲突时，明确指出，获得我的确认再破例。
- 安全重要，但 dev 模式和只给维护者用的功能不过度投入。
- 动作匹配用户当前模式：讨论只读，实施遵循确认的目标与范围，验收评判已有结果；模式转换由用户决定。
- 优化已安装的第三方工具或上游 skill，优先原生配置、操作和指引，保留官方文件。宿主适配保持原工作流，只改命令、工具、路径；改变工作流或功能、修改源码、fork、提上游 PR，须获明确开发授权。
- 删除数据库或重置数据须先获明确同意；删除用途不明的内容前先询问。
- 新建或修改会被 agent 读取并遵循的文本（skill 及其引用文件、AGENTS.md、prompt、子 agent 定义、工作流指令，含一行小改）前，先用 writing-for-agents skill，除非全文已在上下文。
- 确认无真实用户的项目：不做兼容或迁移、不留旧实现备用。先更新文档；行为测试只锁行为，先观察失败再最少实现；核对文档与代码后，清理本次废弃代码、文件和文档。
- 计划、调研笔记和 scratch 不提交进仓库。跨会话要用的反馈原文、计划和报告存到所属项目或主题的持久目录；与当前仓库无关的内容存到仓库外。`/tmp` 只放可丢弃的中间产物。持久名称说明用途，多词用 kebab-case，ASCII 主体可带中文；顺序号仅作不复用的前缀，会话代号不作持久名称。

## 工具与环境

- 只结束自己启动时记下 PID 的进程，或确认 cwd 是本 worktree 的端口占用者。按名字、路径或 worktree 字符串匹配去杀（`pkill -f`、`pgrep | kill`）会误伤自己的 agent 进程和机器上其他 dev server。
- dev server 和构建从自己的 shell 启动，随会话结束；我要求常驻时才用 `nohup`、`setsid`、`tmux`、`systemd-run` 脱离会话，脱离的进程曾连跑数周占满内存和 swap。
- 需要第二个 checkout 时，`git worktree add` 到当前 worktree 旁边，不放 `/tmp`，用完删除。
- 测试用真实数据的副本：复制进沙箱，不软链，不指向正在使用的数据；数据只单向流入。
- 没有合适的标准库或已装依赖时，引入成熟依赖优先于自研。JavaScript 包命令默认 `bunx`，仅用户要求或兼容问题时换 runner。
- 通用 skill 维护在 `~/.agents/skills`，宿主专属留宿主目录，项目私有留项目目录；镜像用软链，同名同用途只维护一份。
- GUI 自动化避免干扰用户当前桌面。本机窗口由 OmniWM 平铺，打开或摆放窗口前先用 omniwm skill。
- 遇到耗时构建、批量测试或批处理任务，主动提醒我可以交给 `kvm` 执行；一次性 KVM 命令用 `hc run --on kvm`。在 KVM 执行重计算时，先走项目已有的执行入口与锁，再按全机 CPU、内存余量（含其他 agent 的任务）主动提高独立任务并发和工具线程数。
- 委派大额未提交改动：简报带基线 ref，先 `--stat`/name-status 定范围，再按分配路径读 diff；附已有门禁日志，不让 worker 重跑。
- 本机环境补充规则：若 `~/.pi/agent/local-environment.md` 存在，读取并遵循；该文件不入库。

## 代码与测试

- 复杂度放在适配器边界：核心逻辑保持纯，UI 保持笨。功能写成 service，传输层（RPC handler、HTTP route、MCP tool）只解码输入、调用一个 service 方法、映射错误。
- 类型靠推断，`any` 是敌人。
- 注释默认不写，只为代码表达不了的约束、外部怪癖或不变量写，能一行就一行，最多四行。名字和签名、步骤、历史、刚做的修复留给 PR。
- UI 组件库的组件自己管外观：选 `variant` 或 `size`，不用 `className` 改样式。通用外观加成新 variant，功能专属外观留在该功能的组件里；宽度、flex、margin、position 写在父级。
- React effect 只用来和 React 外部同步：能推导的在 render 里推导，动作放进事件处理函数；真实的生命周期工作也不藏进 ref 或 store 来回避 effect。
- 不做持续重绘的动画，它们在高刷新率屏幕上占满 GPU。
- 测会坏的行为：编排、协议翻译、鉴权和权限守卫、持久化和迁移、外部格式解析、竞态修复、bug 修复改到的逻辑。类型已保证的、琐碎逻辑、文案、冒烟运行、mock 调用镜像、回调接线、静态渲染不测。
- 先扩展再新增：已有用例或表格覆盖到时，加一行或一个断言。只在一层测：在 main 上会失败的最低一层，不在包装层、各调用点或逻辑副本里重复。
- 浏览器测试只给需要真浏览器的行为：布局和滚动、焦点和指针输入、真 worker、接了 hooks 的组件。组件调用的逻辑写旁边的单元测试。
- 等待靠事件：await 标志里程碑的事件、promise 或队列项。需要 sleep、轮询、单测超时、`retry` 或 wall-clock 差值才能过的测试是错的，flaky 测试修好而不是重试。跳过的测试在上一行写跟踪 issue 和原因。
- 全仓检查交给 CI，我要求时才跑。
- 真实 agent turn 花钱：有免费的 replay 或 mock provider 就用；依赖真实 provider 行为时用它最便宜的模型。

## 文档与 PR

- 多数代码改动不需要改内部文档。内部文档只写架构决策和理由、跨组件约束、读源码难发现的陷阱；读代码能回答的不写，不枚举功能、字段、控制流、文件清单或 PR 摘要。决策变了就改写或删掉原文，不追加新说法。
- 用户文档帮用户完成任务：每个主要功能一段，说清做什么、怎么开始、哪里反直觉；不描述可见的按钮、图标、布局和每种 UI 状态。
- 合并的 PR 就是实现记录，进度跟踪放在 issue 里，仓库里不留第二份清单。
- 我明确要求时才开 PR。第一次用 forge 命令前看 `git remote get-url origin`，用对应 forge 的 CLI。标题用 Conventional Commits、白话；正文先用一两句写问题，再写修法，结尾写做这件事的模型和 harness。UI 改动附前后截图，动效附短视频，证据上传到 forge，不提交进仓库。一个请求一个 PR。
- 照看 PR 时：逐条对照源码核实 bot 的发现，修真的，误报写明理由驳回；没有新情况不发言；最新提交上 bot 全绿即停。

## 审查与收尾

- 完成前逐项检查改动覆盖面并说明哪些适用：同一行为的其他入口；有进入就有退出和可见状态，单向门是 bug；跨进程或网络的契约改了，所有消费方跟着改；现有文档是否因此失真。
- bug 修复的证据按类型：逻辑、数据、状态、协议 bug 先写在 main 上失败的测试再修；纯视觉 bug（间距、颜色、对齐、布局跳动）用前后截图，不加测试；没有可见界面的服务端修复附测试和一段运行记录。
- 审查默认 `ponytail-review`；每次一套，子 agent 遵循分配视角。仅明确要求多 agent 独立复核时，读取并遵循 `~/.pi/agent/skills/multi-agent-review/SKILL.md`。
- 验证覆盖目标与实际风险，采用最小充分检查；复用有效结果，只补缺口或失效证据，满足验收即收口。交付前运行相关测试并亲自检查输出，说明删除项（无则注明）和是否已提交。
- 修复反馈时，完成标准是回放原始或同类场景并确认原错误消失，闪烁、跳动等动态问题逐帧比对过渡帧；测试和分数只作旁证。
- 验证通过或无可运行验证时，自动按照 Conventional Commits 提交改动，后者在交付中注明未验证；补修本任务的 HEAD 且确认未推送时 amend。push 由我发起；hook 失败时修复根因后重新提交。
- 任务结束时主动清理本任务创建的临时资源，包括辅助分支、worktree、子 agent、后台进程和临时文件。
